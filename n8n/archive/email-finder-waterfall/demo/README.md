# Demo, what to run, and what to show

Everything here works with **no API keys and no n8n instance**. That is the point:
the client can see the behaviour before they hand over a credential.

## The two scripts

```bash
node simulate.js     # runs the workflow's real Code nodes through 16 scenarios
python validate.py   # structural check on workflow-v2.json
```

`simulate.js` loads `../workflow-v2.json`, pulls the JavaScript out of every Code node,
and executes it against a mocked n8n context following the same branch logic the engine
would. It is not a re-implementation, edit a Code node in n8n, export, and the script
tests the edit. The assertions at the bottom are the claims this template's README makes,
so a README that drifts from the workflow fails the run.

`validate.py` checks the JSON parses, every connection resolves to a node that exists,
every `$('node name')` reference in every expression and Code node names a real node,
merge inputs fit their declared `numberInputs`, no node is orphaned, and every Code node
parses as JavaScript (`node --check`).

Both exit non-zero on failure, so they belong in whatever runs before a template is sent
to a client.

## The payloads

| File | What it is |
|---|---|
| `request.json` | What Clay posts. Note `domain` arrives as a full URL. The workflow normalises it. |
| `response-dry-run.json` | No keys configured at all |
| `response-verifier-only-guess-confirmed.json` | Only a verifier key: pattern guess, independently confirmed |
| `response-apollo-valid.json` | The good case |
| `response-apollo-catchall.json` | Real address on a catch-all domain |
| `response-all-providers-missed.json` | Every provider ran, nobody knew |

## The demo, in the order that lands

**1. Run it with nothing configured.** `response-dry-run.json`:

```json
{ "email": "", "confidence": 0, "recommended_action": "do_not_send",
  "providers_skipped": ["apollo", "rocketreach", "verifier"] }
```

> "With no providers wired, it built the guess `jane.doe@acme.example` and then threw it away,
> because nothing confirmed it. It also tells you *why* it has nothing, `providers_skipped`
> separates 'we looked and found nothing' from 'we never looked'. Most enrichment setups
> can't tell you which one happened."

**2. Add only the verifier key and run again.** `response-verifier-only-guess-confirmed.json`
,  same guess, now `confidence: 55`, `recommended_action: "review"`.

> "One credit, four tenths of a cent. The guess survived because a third party confirmed
> the mailbox exists. And it still isn't cleared to send, because a confirmed guess is
> not the same thing as a sourced address."

**3. Show the catch-all case.** `response-apollo-catchall.json` — `confidence: 75`, above
the send line, and still `"recommended_action": "review"`.

> "A catch-all domain accepts every address, so 'it didn't bounce' proves nothing about
> that mailbox. It scores well and it still goes in its own segment, sent last and watched
> on its own. That rule is in the workflow, not in a document somebody has to remember."

Three runs, and the entire argument is made, with no credential in anyone's hands yet.

## Regenerating these

They are generated by `simulate.js`, not written by hand, so they cannot drift from the
workflow. Re-export from n8n over `../workflow-v2.json` and re-run the scripts.
