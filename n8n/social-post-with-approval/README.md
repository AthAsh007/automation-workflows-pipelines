# Acme LinkedIn daily

The `workspace/tutorials` LinkedIn pipeline, as two n8n workflows.

Every weekday at 08:00 it picks the next post from the bank, writes or reads its caption, checks
it in code, renders the 1080×1350 image from HTML, and puts the draft in Discord. A human replies
`post`, `cancel`, or `edit` with a better caption, and the second workflow acts on it. Nothing
publishes without a `post`.

| | |
|---|---|
| [`01-draft-and-approve.json`](01-draft-and-approve.json) | 57 nodes. Weekdays 08:00 + manual. Rotate → write → check → rewrite once → render → Discord. **Never publishes.** |
| [`02-publish-on-approval.json`](02-publish-on-approval.json) | 74 nodes. Every 5 min + manual. Expire / read the reply → edit, cancel or publish → alert → log. Weekly report. |
| `*-publish.json` | The n8n template-library copies: same graph, de-identified, generated by the build. |

**Both ship in PREVIEW and run end to end with no credentials at all.** Import both and hit
*Execute workflow*:

- **01** reads a demo log and the demo bank. Topic rotation holds slot 1 (its pillar went out two
  days ago), slot 2 has no caption, so the demo writer drafts one that breaks four rules (recycled
  hook, a link, a banned phrase, eight hashtags). The check catches all four, the rewrite fixes
  them, the layout passes, and the run renders the PNG if Browserless is reachable or stops at
  `STOP: no image` with the reason if it is not. Either way nothing is sent.
- **02** reads a demo log with one open draft and a demo channel holding the reviewer's reply
  (`DEMO_REPLY` in `config`: `post`, `cancel`, `edit`, `bad-edit`). It also builds the weekly
  report from the demo week.

## What changed in the October 2026 pass

The template came back from the n8n Creator Hub as "too basic". Reading it again, the depth was
mostly in places a reviewer never sees, and several real defects were hiding behind the demo
stopping early. What was added, and what was fixed:

**Added**

| | Where |
|---|---|
| Topic rotation by calendar date from the log (pillar cooldown, topic-family cap) | `pick todays post` |
| Caption rules for links, @mentions, hashtags off the last line, and a repeated opening hook vs. recent posts | `lib/caption-rules.js`, shared by 3 nodes |
| One rewrite of a failing model caption, with its answer and the exact failures fed back, then hold for a human | `build the rewrite brief` → `check the rewrite` |
| `edit` replies: checked against the same rules, re-delivered with the original image as a new draft, or refused once with reasons | `check the edited caption` and its two branches |
| Expiry that actually closes the draft (`expired` row) | `what state is the draft in?` |
| Token problems caught on the harmless first LinkedIn call, alerted once per 6 h, approval kept open | `read the upload registration` → `build the LinkedIn alert` |
| Early warning N days before the token expires | `build the run summary` |
| Weekly report from the log, with LinkedIn post statistics when the app has access | lane 2 of workflow 02 |
| A real no-credential demo path in both workflows | `load the demo log`, `load the demo channel`, demo writers |

**Fixed** (each has a regression check in `simulate.js`)

- *Day-2 deadlock.* `find the pending draft` treated every `awaiting` row ever written as open. The
  log is append-only, so the second day's draft made two, and every poll after that stopped at
  "conflict". Open now means "no later row with the same message id closes it".
- *A cancelled day stayed silent.* `resolve todays state` checked for an `awaiting` row before a
  `cancelled` one, so the day's original row kept it silent.
- *Expired drafts were never closed*, so the next day's draft collided with them.
- *Approvals could never publish.* `the approved draft` looked for the Discord message in its
  input items, which by then held only the decision. The draft message now travels with the
  decision.
- *The posted row was built from the wrong data.* It ran after the bank-row write and read that
  node's echo, so it was logged as `failed` with no URN.
- *Helper fields became sheet columns.* Auto-mapped appends default to `insertInNewColumn`; every
  write now ignores fields that are not headings.
- *Every grid post failed layout* (the band is the grid's focal element but carries no `focal`
  class).
- *The demo never got past the caption* (40-word demo captions, a 120-word minimum), and Sheets
  nodes had no gate, so a credential-less run failed on node 2.
- *Slack every five minutes.* Idle polls are now quiet.
- The Discord node's **Files** binding is now set in the JSON (`files.values[].inputFieldName`).

## Setup

### 1. Import

Both working JSON files (or both `-publish.json` copies). n8n → Workflows → Import from File.
Nothing has a credential attached; every node that needs one is prefixed `[cred]`.

### 2. A renderer

n8n has no browser. Add Browserless to the same `docker-compose.yml` n8n runs in:

```yaml
  browserless:
    image: ghcr.io/browserless/chromium:latest
    restart: unless-stopped
    environment:
      - CONCURRENT: 2
      - TOKEN: ${BROWSERLESS_TOKEN}
    networks: [ default ]
```

Then in `config`: `RENDER_URL = 'http://browserless:3000'` and `RENDER_KEY` = that token.

> **Queue mode.** Code nodes execute on the *worker* containers. Browserless must be on the
> network the workers can reach, not just the main `n8n` container.

htmlcsstoimage.com works as a hosted alternative: `RENDER_PROVIDER = 'hcti'` plus
`RENDER_USER` / `RENDER_KEY`.

### 3. The logo

Paste the contents of `render/acme_logo_12.svg` into `LOGO_SVG` in `config`. The renderer
loads the HTML with no network, so the SVG has to travel inline. Blank is a warning in preview
and a hard block the moment a draft would actually be delivered: a missing logo must look missing.

### 4. The sheet

Two tabs, headings exactly as in [`sheet/Bank.csv`](sheet/Bank.csv) and
[`sheet/Log.csv`](sheet/Log.csv). Import [`sheet/seed-bank.csv`](sheet/seed-bank.csv) into
**Bank**: the real draft bank, all sixteen posts, exported from the drafts repo by
`build/export_bank.js`. Slots 1–8 arrive marked `posted`.

> **Upgrading an existing Log tab:** add the columns `Reply id`, `Pillar` and `Hook` (anywhere).
> Old rows without them still read correctly; rotation and the hook check start from the first
> post logged with them.

| Tab | What it is |
|---|---|
| **Bank** | One row per post, in publish order. `Items` is a JSON array whose shape depends on `Layout`. `State` is `ready` until it goes out. |
| **Log** | Append-only. **The source of truth for what has happened.** Never edited, only appended to. |

Log statuses: `awaiting` opens a draft; `posted`, `cancelled`, `expired`, `superseded` and
`failed` close it (same `Message id`); `edit-refused`, `alert` and `report` annotate without
closing.

### 5. Discord

A **private** channel, created for this and nothing else.

> Anyone who can send a message in that channel can publish to the company LinkedIn page.
> Treat send-permission there as equivalent to page publishing rights.

The bot needs View Channel, Send Messages, **Attach Files**, Embed Links and Read Message
History. Put the channel id in `DISCORD_CHANNEL_ID`. The PNG is attached through the node's
**Files** option (binary property `data`); it is set in the JSON, but open each Discord send node
once after import to confirm it survived.

### 6. LinkedIn

`LINKEDIN_ORG_URN` is the Acme page. `LINKEDIN_ACCESS_TOKEN` needs `w_organization_social`.
Put its expiry date in `LINKEDIN_TOKEN_EXPIRES_ON` and the daily summary warns
`TOKEN_WARN_DAYS` ahead. (The 2026-08-18 token lapsed on 2026-10-17 with nothing to say so; that is
the failure this exists for.)

`LINKEDIN_VERSION` is `202608`. A retired version returns HTTP 426 and is reported by name.

`STATS_ENABLED` adds per-post impressions/clicks/reactions to the weekly report via
`organizationalEntityShareStatistics`. That needs `r_organization_social`, which LinkedIn gates
behind Community Management API approval, the same gate that returns 403 on `socialActions` for
this app today (see `linkdin-drafts/POSTED.md`). It ships `false`; a 403 is reported as the gate,
not as a failure.

### 7. Going live

Two separate acts, in this order:

1. `TEST_CHANNEL_ID = '<a test channel>'` → drafts are delivered there. **Still cannot publish.**
2. `TEST_RUN = false` → the live channel, and an approval there publishes.

Both workflows must carry the same `config`; `validate.mjs` fails the build if they drift.

## How a day actually goes

```text
08:00  workflow 01
       ├─ read the log ──> resolve todays state
       │       open draft (any day, not expired)? silent.  posted today? silent.
       │       cancelled today, or the open one has expired? draft.
       ├─ pick todays post   lowest ready slot that survives:
       │       layout / pillar repeat in the slot window, Design-on-Thursday,
       │       pillar published < 21 days ago, 2+ posts from its family this week
       ├─ who writes the caption?   bank cell | model | demo writer | nobody
       ├─ apply the caption   length, hashtags (count + last line), emoji, banned phrases,
       │                      links, @mentions, hook ≈ a recent hook
       │       fails + model-written? one rewrite with the failures fed back, checked again
       │       still fails, or banked? STOP: caption held
       ├─ build the HTML ──> validate the layout ──> render ──> check the PNG bytes
       └─ Discord (caption + image) ──> `awaiting` row

…      workflow 02, every 5 minutes
       ├─ the log ─┬─> find the pending draft
       │           │     none? STOP (quiet).  expired? `expired` row.  two open? STOP: conflict.
       │           └─> weekly report due? (Mon 09:00, once per week via a `report` row)
       ├─ read the channel ──> read the approval reply
       ├─ post   ──> unchanged since delivery? ──> register upload
       │               token rejected? alert once / 6 h, approval stays open
       │             ──> PUT bytes ──> publish (no retry) ──> bank row ──> `posted` + URN
       ├─ edit   ──> caption rules ──> pass: re-deliver with the same image (`superseded` + new `awaiting`)
       │                            └─ fail: reply with reasons (`edit-refused`), original stays open
       ├─ cancel ──> `cancelled`. The bank row stays `ready`.
       └─ nothing ──> wait (quiet)
```

Two rules that must not be reintroduced:

- **A rendered image is not evidence of a post.** It is written at draft time.
- **There is no cascade rule.** A run is silent because today's log says so, for no other reason.

## The approval gate

`read the approval reply` is the node that matters. Every rule in it is a refusal:

| Rule | Why |
|---|---|
| Only messages after the draft | anything already in the channel cannot be a reply to it |
| Never the bot's own message | it posted the draft, that is the system agreeing with itself |
| Never another bot | a second automation is not a second opinion |
| `post` / `cancel` must be the whole message | substring matching makes **"do not post"** an approval |
| `edit` must be the whole first line, with text under it | an edit is a decision about words, so it needs words |
| Replies already acted on are skipped | a refused edit is answered once, and a later `post` can still approve the original |
| First decision wins | a cancel is not reopened by a later `post` |

An **edit never publishes**: it becomes a new draft with its own fingerprint and needs its own
`post`. The person approving is always looking at the exact message that will be published.

Before publishing, `the approved draft` takes the caption **from the Discord message** (what the
human read), proves with the fingerprint written at delivery that it has not been edited since,
and takes the image from the same message.

## Working on it

```bash
cd build
bun simulate.js            # 130 checks, no network, ~2s
bun simulate.js --render   # + a real Chrome screenshot into sample/preview.png
bun build.mjs              # js/*.js -> ../01-*.json, ../02-*.json and both -publish.json
bun validate.mjs           # structure, references, stickies, the safety switch, de-identification
bun export_bank.js         # regenerate sheet/seed-bank.csv from the drafts repo
```

The Code nodes live in `build/js/` as real `.js` files; `js/lib/` holds the rules shared by several
nodes, inlined by `// @include`. **Nothing is hand-edited in the JSON.** The sticky notes come
from `build/stickies.json` (also written into `n8n/tools/stickies-resubmit-2026-10.json`), using
the same geometry as `tools/restyle_stickies.mjs`, so running that tool reproduces this layout
byte for byte.

## Known limits

- **The poll is five minutes.** An approval waits up to that long.
- **The caption cannot exceed 2000 characters**, Discord's message limit. Over that it is held.
- **`validate the layout` cannot see pixels.** A human still looks at the PNG in Discord.
- **No image-model fallback, on purpose.** A failed render is a failure.
- **Hook similarity is word overlap**, not meaning. It catches a recycled opening, not a
  paraphrased one.
- **Comments are not automated.** `socialActions` is product-gated for this app (403).
- **One brand.** MCH is a second copy of this folder, not a switch in this one.
